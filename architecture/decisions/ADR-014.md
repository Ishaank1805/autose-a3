# ADR-014 — Enforce strict maintainer protocols for provider quota resets and documented design-change PRs

**Status:** Accepted
**Date:** 2026-11-24

## Context

During the execution of Campaign 2, Account B reached its daily request quota on the Google Gemini free tier during the repetition of the D1 decision experiment. To work around the pause and continue pipeline execution without waiting for the scheduled quota reset, the maintainer opened and merged [PR #35](https://github.com/Ishaank1805/tinydb/pull/35), switching the reviewer model from `gemini-3.1-flash-lite` to `gemini-3.5-flash-lite`.

Although all 40 seeded PR reviews (the core evaluation of Reviewer v2 vs. v1 on S1–S10) had already concluded before this switch, six full D1 runs (Issues 3–5 for both baseline and single-agent variants) were evaluated under the alternative model. Following the campaign, [PR #36](https://github.com/Ishaank1805/tinydb/pull/36) reverted PR #35 to restore the canonical configuration.

This incident demonstrated that operational workarounds can introduce uncontrolled confounding variables into experimental evaluations. ADR-009 addressed automated runtime failures within the sandbox, but operational protocols for the pipeline maintainer were previously uncodified.

## Decision

Establish formal operating procedures for the pipeline maintainer governing quota limits and workflow changes:

- **Strict Quota Pause Protocol**: When a provider quota ceiling is encountered (HTTP 429 or quota error response), the maintainer must stop the active stage cleanly, record the state, and pause execution until the provider's daily quota reset window (13:30 IST for Google Gemini). Mid-campaign model substitutions or parameter alterations are strictly prohibited.
- **Formal Pull Request Workflow**: Any modification to workflow definitions (`.github/workflows/*.yml`), harness code (`.github/autose/**`), or configuration files (`autose.config.yml`) must follow formal change control:
  1. Implemented on a dedicated feature branch (e.g., `design/*`, `fix/*`, `revert/*`).
  2. Verified by running the local test suite (`pytest -q .github/autose/tests`).
  3. Submitted as a GitHub Pull Request with explicit labels (`design-change` or `infra`).
  4. Documented with rationale in `results/fixes.md`.
  5. Squashed and merged to `main` with remote branch deletion.

## Consequences

This policy eliminates mid-campaign protocol drift and guarantees that all experimental runs remain strictly comparable under documented parameters. While waiting for quota resets introduces scheduling delays, it protects scientific validity and auditability. This decision complements ADR-009 by hardening external operational boundaries.
