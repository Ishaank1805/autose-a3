# ADR-012 — Allocate dual Flash-Lite models on two Gemini API accounts with 6.5-second pacing and an 80-minute build budget

**Status:** Accepted (Supersedes ADR-006)
**Date:** 2026-11-22

## Context

ADR-006 originally allocated Anthropic Claude models (Sonnet for code generation, Haiku for judging, Opus for review) with a 55-minute soft job timeout and a 75-minute hard limit. In deployment, commercial API cost constraints necessitated migrating the entire AutoSE pipeline to the Google Gemini free tier.

The Gemini API free tier imposes stringent rate limits: approximately 500 requests per day and 10 requests per minute per project. To avoid 429 rate limit errors, the harness enforced a mandatory 6.5-second pacing delay between consecutive LLM calls. In Campaign 1, red-team confirmation run [44751912678](https://github.com/Ishaank1805/tinydb/actions/runs/44751912678) reached the testing stage but stopped prematurely due to timeout: "time budget exhausted (58 > 55 min)". The combination of request pacing, multi-step agent reasoning, and multiple submissions consumed more wall-clock time than the initial 55-minute budget permitted.

## Decision

Reconfigure model allocation, account routing, and job execution timeouts across `.github/autose/autose.config.yml` and `.github/workflows/autose-build.yml`:

- **Model Allocation**: Deploy two lightweight models through Gemini's OpenAI-compatible endpoint:
  - `gemini-3.5-flash-lite`: Assigned to the Planner, Implementer, and Single-Agent Generalist roles for codebase exploration and code editing.
  - `gemini-3.1-flash-lite`: Assigned to the Test Author, Reviewer, and Testability Judge roles for test generation, evaluation, and verification.
- **Dual Account Partitioning**: Distribute traffic across two separate Google accounts with static role bindings (no alternating requests within a role):
  - *Account A* (`GEMINI_API_KEY`): Serves the build job roles (planner, implementer, test author, and judge).
  - *Account B* (`GEMINI_API_KEY_2`): Serves the independent reviewer job and the single-agent variant.
- **Budget Expansion (PR #24)**: Increase the build job soft budget from 55 to 80 minutes (`time_budget_minutes: 80`) and the GitHub Actions hard timeout from 75 to 95 minutes (`timeout-minutes: 95`).
- **Pacing**: Maintain 6.5-second pauses between requests to stay strictly within 10 RPM.

## Consequences

Total token consumption across all 80 protocol runs reached 21,668,554 tokens at an estimated financial cost of exactly $0.00. Following PR #24, zero runs in Campaign 2 stopped due to time budget exhaustion.

The trade-offs include operational latency (full runs require 40–70 minutes), daily quota pauses when hitting the 500-request ceiling (which occurred twice, requiring pauses until the 13:30 IST reset), and higher reasoning variance inherent to Flash-Lite models at requirements and design compared to frontier models.
