# ADR-003 — Pass structured, sanitised artifacts between stages and deliberately withhold implementer reasoning from the reviewer

**Status:** Accepted — baseline

## Context

Agents need enough prior work to act consistently, but full transcripts are long, include unverified reasoning, and create anchoring. The assignment specifically requires an independent reviewer that does not merely agree with the implementer.

The bundle already produces the required artifacts (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, and `review.md`) and wraps issue, PR, and other human-authored text as untrusted data.

## Decision

Use the following minimum hand-offs.

| Receiving stage | Receives | Deliberately does not receive |
|---|---|---|
| Design | Sanitised issue snapshot, accepted `spec.md`, `ARCHITECTURE.md`, repository checkout | Planner transcript |
| Implementation | `spec.md`, `design.md`, relevant repository files, bounded feedback | Planner transcript and test-author work |
| Testing | Acceptance criteria, planned tests, current checkout, limited implementer dispute/failure feedback | Implementer transcript |
| Release | Commit state and deterministic check results | Model reasoning |
| Review, baseline | Sanitised issue snapshot, PR diff, repository at PR head, test command | `spec.md`, `design.md`, `test_report.md`, `pr.md`, all transcripts, and any implementer explanation |

Artifacts are written by the harness and uploaded after every job. When a stage repeats, the harness preserves versioned history rather than replacing the evidence silently.

## Consequences

The implementation has traceable contracts without treating a prior agent's rationale as authoritative. The reviewer has only evidence it could reasonably obtain from the issue and PR, which is stronger independence than merely using a different prompt. The cost is that a reviewer may flag an intentional choice whose rationale it cannot see; it should ask for rework only for a concrete blocker or major fault. The `reviewer-sees-rationale` variant tests whether adding `design.md` and `pr.md` raises agreement while reducing defect detection.
