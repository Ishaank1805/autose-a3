# ADR-010 — Restrict triggers to trusted actors, protect the target repository, and serialize work per issue

**Status:** Accepted — baseline

## Context

The assignment asks for label/comment triggers, but a public issue tracker also permits arbitrary commenters. Multiple runs on one issue could create conflicting bot branches and PRs. The workflow must never modify the original upstream repository.

## Decision

Support these explicit entry points:

- adding the exact `autose` label to an open issue;
- `/autose` or `/autose run` on an issue;
- `/autose review [#issue]` on an open PR for review-only experiments;
- maintainer-initiated `workflow_dispatch` in the Actions UI.

The gate ignores bot comments, unknown command arguments, closed issues, labels on pull requests, and non-AutoSE events. For event triggers it queries the actor's repository permission and requires at least `write`; manual dispatch is already limited to users allowed to dispatch workflows. It validates the configured allow-list `repository.allowed: [Ishaank1805/tinydb]`, and review preparation rejects PRs whose base or head repository is not that repository.

Use `concurrency.group: autose-<issue-number>` with `cancel-in-progress: false`. Thus one issue has one active workflow while separate issues can proceed concurrently. Baseline and experimental variants use distinct branch names such as `autose/issue-<N>-single-agent`, avoiding overwrite of the baseline branch.

## Consequences

Drive-by issue comments cannot start a secret-bearing run, forks cannot smuggle code into the review job, and concurrent requests do not displace in-progress work. A second trigger for the same issue queues instead of cancelling a valid run; this is safer but may delay maintainers. Branch protection on `main` remains necessary because this workflow's no-merge guarantee does not prevent a human or another token from bypassing it.
