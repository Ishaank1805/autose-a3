# ADR-013 — Deploy Reviewer v2 with AST diff facts, pre-change tree rebuild, differential probes, and mandatory probe gate

**Status:** Accepted (Supersedes ADR-008)
**Date:** 2026-11-22

## Context

In Campaign 1, the baseline independent reviewer approved all three defective seeded pull requests (S2, S3, S4), achieving 0/3 defect recall and 100% false approvals. The author-rationale experiment demonstrated that providing implementer reasoning caught S4 (1/3), but giving the reviewer builder context compromised independence.

To improve skeptical scrutiny without violating role independence, we designed **Reviewer v2** (PR #25, with path fixes #31 and #32). Reviewer v2 provides objective structural data derived from the diff, rebuilds the pre-change repository commit from the PR diff via `difffacts.py`, provides `bash $SCRATCH/compare.sh <script.py>` to execute differential tests before and after the change, and mandates that approval requires running at least one probe.

## Decision

Adopt Reviewer v2 as the default reviewer architecture:

- **Harness Diff Facts**: Statically compute and inject AST facts into the reviewer prompt: modified, added, and deleted functions/classes, existing test cases altered by the diff, and touched functions not mentioned in the PR title.
- **Pre-Change Code Reversal**: Rebuild the repository state immediately preceding the change into a scratch directory outside the repository checkout, refusing rebuilds if `git apply -R` skips files (PR #37).
- **Differential Execution**: Provide `$SCRATCH/compare.sh` allowing probe scripts to run against both pre-change and post-change code and report stdout diffs.
- **Probe Gate**: Reject approval if the reviewer has not executed at least one probe script.
- **Model & Independence**: Retain `gemini-3.1-flash-lite` on Account B with no prior stage transcripts or builder reasoning.

## Consequences

In Campaign 2, across 40 seeded PR reviews (two full repeats across Dev set S1–S5 and Held-out set S6–S10):
- **Precision**: 100% across all 40 reviews. Clean PRs were approved in 16/16 reviews with 0 false alarms.
- **Defect Recall**:
  - *Dev set (S1–S5)*: Reviewer v2 caught 1/6 (17%) vs. Reviewer-v1 2/6 (33%).
  - *Held-out set (S6–S10)*: Reviewer v2 caught 2/6 (33%) vs. Reviewer-v1 3/6 (50%).
- **Repeat Consistency**: Reviewer v2 achieved 4/5 (80%) on dev and 3/5 (60%) on held-out, compared to 5/5 (100%) and 4/5 (80%) for v1.

The data plainly shows that Reviewer v2 did not achieve higher recall than Reviewer v1. Error analysis across 30 reviews of defective PRs shows that 10 defects were missed because probes never targeted the bug, 6 were missed because no probe was written, and 5 were missed even though a probe exposed the defect ("approved anyway"). However, Reviewer v2 is retained in the final workflow because differential probing succeeded in exposing defects in S7 and S8 without any regression in precision.

Future proposals (unimplemented) to improve recall include multi-reviewer voting ensembles, property-based probe generation, and stronger reasoning models.
