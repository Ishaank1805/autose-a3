# Architectural Decision Records (ADR) Audit

This document audits ADR-001 through ADR-010 against the actual implementation in the repository (`.github/workflows/` and `.github/autose/`). Every concrete statement regarding components, models, stage checks, permissions, and command interfaces was verified against source code.

## Audit Matrix

| ADR | Statement in ADR | Code Implementation | Path in Repository | Action |
|:---|:---|:---|:---|:---|
| **ADR-001** | Planner role covers both requirements and design in one shared session. | Requirements and design use the same model role (`planner`), but are executed as distinct stages in fresh agent sessions communicating via `spec.md`. | `.github/autose/autose/orchestrator.py`<br>`.github/autose/autose/stages/requirements.py`<br>`.github/autose/autose/stages/design.py` | **Erratum** (session independence) |
| **ADR-001** | Named models: Claude Sonnet, Haiku, Opus. | System executes with Google Gemini models (`gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`). | `.github/autose/autose.config.yml`<br>`.github/autose/autose/llm.py` | **Superseded by ADR-012** |
| **ADR-002** | Workflow controller is implemented in `workflow/controller.py`. | Controller and state machine are implemented in `autose/orchestrator.py`; no `workflow/` directory exists in the fork. | `.github/autose/autose/orchestrator.py` | **Erratum** (file path) |
| **ADR-002** | Deterministic state machine controlling stages 1–5 with unrolled GitHub Actions review DAG. | Verified: state machine bounds submissions to 3, unrolls `review_1` to `review_3` in Actions DAG. | `.github/workflows/autose.yml`<br>`.github/autose/autose/orchestrator.py` | **Verified** |
| **ADR-003** | Structured artifacts passed between stages; implementer reasoning withheld from reviewer. | Verified: artifacts persisted via `ctx.state`; reviewer prompt receives PR diff, issue text, base repo head, and diff facts, but no implementer reasoning. | `.github/autose/autose/context.py`<br>`.github/autose/autose/review.py` | **Verified** |
| **ADR-004** | Actions artifacts and live issue status comment store state; no promise of automatic resume. | Verified: state stored in artifacts (`autose-issue`, `autose-state-r<N>`, `autose-review-r<N>`); gate does not support an `/autose resume` command. | `.github/autose/autose/gate.py`<br>`.github/workflows/autose.yml` | **Verified** |
| **ADR-005** | Job-level separation of write permissions: gate read-only, build write, review read-only. | Partially verified: `gate` and `review` have restricted tokens. However, inside `autose-build.yml`, both agent execution (stages 1–4) and deterministic release (stage 5) run on the same runner job. Write separation is enforced at the process/sandbox boundary by `secretstore.py`, not across separate Actions jobs. | `.github/workflows/autose-build.yml`<br>`.github/autose/autose/secretstore.py` | **Erratum** (job vs process boundary) |
| **ADR-006** | Claude model allocation across roles; 55-minute soft / 75-minute hard timeout. | System uses Gemini free-tier models across two accounts with 6.5s pacing; build job timeouts were raised to 80m soft / 95m hard in PR #24. | `.github/autose/autose.config.yml`<br>`.github/workflows/autose-build.yml` | **Superseded by ADR-012** |
| **ADR-007** | LLM testability judge is advisory unless configured required; design check requires Python functions for all plans; soft fail-to-pass. | 1. Judge verdict is blocking when available: if an AC is marked untestable, `result.problems` fails the check.<br>2. PR #23 added documentation-only plan bypass for the Python function check. | `.github/autose/autose/stages/requirements.py`<br>`.github/autose/autose/checks.py` | **Superseded by ADR-011** |
| **ADR-008** | Reviewer isolation and baseline prompt; run suite and write probe before approval. | Reviewer v1 approved all 3 defective seeded PRs in Campaign 1. Reviewer v2 was implemented in PR #25 (AST diff facts, pre-change tree rebuild, `compare.sh`, probe gate). | `.github/autose/autose/review.py`<br>`.github/autose/autose/difffacts.py` | **Superseded by ADR-013** |
| **ADR-009** | Untrusted content sanitization, command deny-list, budget exhaustion handling. | Verified: HTML comments stripped in gate (100% in red-team runs); subprocess commands scrubbed and timeouts enforced. | `.github/autose/autose/gate.py`<br>`.github/autose/autose/untrusted.py`<br>`.github/autose/autose/sandbox.py` | **Verified** (complemented by ADR-014) |
| **ADR-010** | Trusted actor permissions check (`write`), repo allow-list, concurrency serialization. | Verified: write access verified by gate; `concurrency.group: autose-<issue-number>` prevents concurrent collision; only `/autose [run]` and `/autose review` parsed. | `.github/autose/autose/gate.py`<br>`.github/workflows/autose.yml` | **Verified** |
