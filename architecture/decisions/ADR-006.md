# ADR-006 — Allocate model capability by role and evaluate reviewer diversity experimentally

**Status:** Accepted — baseline

## Context

Requirements, implementation, and test generation need strong code and repository reasoning, but the pipeline must fit a controlled budget. Review has a higher cost of error: a false approval lets an unsafe change appear validated. The effect of reviewer model diversity should be measured rather than assumed.

## Decision

Configure the baseline as follows:

| Role | Baseline model | Rationale |
|---|---|---|
| Planner, implementer, test author | `claude-sonnet-5-5` | Capable coding/reasoning at lower cost than the review model |
| Testability judge | `claude-haiku-5-5` | Narrow, no-tool classification task |
| Reviewer | `claude-opus-5-5` | Stronger, separately prompted sceptical review |

Use a 16,000-token per-agent response cap, role-specific tool-step caps, a 2.5 million token and US$6 per-job budget, 55-minute soft job limit, 75-minute build hard limit, and 45-minute review hard limit. Store usage in the run artifact and report totals.

Keep `reviewer-same-model` as an experiment: run the same seeded PRs with Sonnet as reviewer and compare blocker/major-finding recall, precision, false approvals, token use, and latency against the Opus baseline.

## Consequences

The workflow spends more on an independent final check than on routine planning. Different models alone do not establish independence, so ADR-008 also isolates context and privileges. Model identifiers and prices are configuration values, not architecture constants; the final report must state the actual provider, model versions, date, and spend used in live runs.
