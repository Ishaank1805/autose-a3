Adds `TinyDB.rename_table(old_name, new_name)` as requested in the linked issue.

- Documents and their IDs are moved as-is, so nothing gets renumbered
- The change is written through the storage, so it is persisted like any other write
- Refuses to overwrite an existing table (`ValueError`)
- Clears the cached table objects for both names, so nobody gets stale query results

To keep error handling consistent I extracted a small `_require_table()` helper that both `drop_table()` and `rename_table()` use, and adjusted `test_drop_table` accordingly. Everything is green.
