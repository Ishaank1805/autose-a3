Fixes `update_multiple()` silently ignoring all but the first document when it is given a generator.

The updates iterable was iterated once per document, so a generator was exhausted after the first document. It is now materialized with `list()` up front. While in there I also made sure a document is only updated once per call, which keeps the returned ID list free of duplicates — previously a document matching two conditions showed up twice.

- `tinydb/table.py`: materialize `updates`; update each document once
- `tests/test_tinydb.py`: new test with a generator input

I tested this thoroughly: the full suite passes and the generator case from the issue now updates every product. This is a safe, minimal change.
