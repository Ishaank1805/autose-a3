Fixes the query-cache collision reported in the linked issue.

`fragment()` built its hash from the fragment document only, so `Query().billing.fragment(x)` and `Query().shipping.fragment(x)` compared equal and `Table.search()` served one query's cached results for the other. The path is now part of the hash, the same way every other query test does it.

- `tinydb/queries.py`: include `self._path` in the fragment hash
- `tests/test_queries.py`: regression test for equality/hash of fragments on different paths

All existing tests pass.
